# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.


## Repository Overview

The **Overleaf Toolkit** is a set of bash scripts for running a local instance of [Overleaf](https://overleaf.com) (Community Edition or Server Pro) via Docker Compose. The toolkit is the user-facing wrapper — the Overleaf software itself lives in separate Docker images (`sharelatex/sharelatex` for CE, `quay.io/sharelatex/sharelatex-pro` for Server Pro).

The toolkit contains no application logic for Overleaf itself; its job is to:
1. Generate a per-user `config/` directory from `lib/config-seed/` defaults.
2. Assemble the right `docker-compose.yml` fragments for the user's chosen options.
3. Provide convenience wrappers (`bin/up`, `bin/logs`, `bin/doctor`, etc.) around `docker compose`.


## Top-Level Layout

```
bin/        User-facing scripts (the main interface)
config/     User-owned config (gitignored, generated by bin/init)
data/       Persistent data (gitignored, mounted into containers)
lib/        Toolkit internals — compose fragments, defaults, shared shell functions
doc/        User-facing documentation
.github/    Issue & PR templates
```

`config/` and `data/` are intentionally gitignored — only `config/.gitkeep` and `data/.gitkeep` are tracked.


## Commands

There is no compiled language or test suite in this repo. "Build" / "lint" are shell-level tasks.

### Lint

```sh
bin/dev/lint          # runs shellcheck over every file under bin/
```

The lint helper (`bin/dev/lint`) is the only entry point defined under `bin/dev/` — add new dev helpers there rather than at the top of `bin/`.

### Initialise a local config

```sh
bin/init              # writes config/overleaf.rc, config/variables.env, config/version
bin/init --tls        # additionally seeds config/nginx/ + sample self-signed certs
```

`bin/init` refuses to overwrite an existing config and generates a random `OVERLEAF_INVITE_TOKEN_SECRET` via `openssl rand -base64 32` into `config/variables.env`.

### Run the stack

```sh
bin/up                # foreground (Ctrl-C stops it)
bin/up -d             # detached
bin/start             # start stopped containers
bin/stop              # stop running containers
bin/docker-compose …  # passthrough to docker compose (the underlying engine)
```

### Diagnose

```sh
bin/doctor            # print host info, dependency versions, config summary, warnings
```

### Logs / debugging

```sh
bin/logs -f web clsi                # tail specific in-container services
bin/logs -n 100 -f filestore        # bounded lines + follow
bin/logs -n all web > web.log       # dump to file
bin/error-logs -f web               # filtered: only docker compose headers + level":50 lines
bin/shell                           # exec a bash shell in the sharelatex container
bin/mongo                           # mongosh into the mongo container
bin/run-script [ls|SCRIPT.js …]     # run a node script inside /overleaf/services/web
bin/images                          # list relevant docker images on the host
```

### Upgrade

```sh
bin/upgrade                       # git pull + optional docker image bump
bin/upgrade --skip-git-update     # image bump only
```

`bin/upgrade` reads `lib/config-seed/version`, compares to `config/version`, prompts before rewriting. It also offers to stop the stack, run `rebrand_sharelatex_env_variables` on `config/variables.env` when crossing the major-version-5 boundary, and offer to start the stack back up.

### Backup / migration

```sh
bin/backup-config [-m copy|zip|tar] DEST
bin/rename-rc-vars                  # SHARELATEX_* → OVERLEAF_* in config/overleaf.rc
bin/rename-env-vars-5-0             # SHARELATEX_* → OVERLEAF_* in config/variables.env
```


## Architecture

### Script conventions

Every executable in `bin/` starts with the same boilerplate:

1. `set -euo pipefail`
2. A `realpath` fallback for macOS (which lacks the binary).
3. Compute `TOOLKIT_ROOT` from `BASH_SOURCE[0]` and assert `bin/` + `config/` exist.
4. `source "$TOOLKIT_ROOT/lib/shared-functions.sh"` when needed.

When adding a new `bin/*` script, copy the toolkit-root-detection block verbatim and only `source shared-functions.sh` if you need the helpers (`read_config`, `read_image_version`, `read_mongo_version`, `set_server_pro_image_name`, `set_git_bridge_image_name`, `check_retracted_version`, `check_sharelatex_env_vars`, `prompt`, `rebrand_sharelatex_env_variables`, `read_variable`, `read_configuration`).

### `lib/shared-functions.sh` — the helpers

The single source of truth for configuration parsing:

- `read_config` sources `lib/default.rc` first, then `config/overleaf.rc` (user overrides). It also force-disables `GIT_BRIDGE_ENABLED` for non-Server-Pro or pre-4.0 image versions.
- `read_image_version` parses `config/version` into `IMAGE_VERSION_MAJOR/MINOR/PATCH`.
- `read_mongo_version` enforces the split `MONGO_IMAGE` + `MONGO_VERSION` config (since Mongo 6.0) and picks `mongo` vs `mongosh`.
- `set_server_pro_image_name` / `set_git_bridge_image_name` resolve the final `:tag` for the Overleaf and git-bridge images.
- `check_retracted_version` blocks startup on known-bad versions (currently 5.0.1 — the history-system data-loss bug) unless `OVERLEAF_SKIP_RETRACTION_CHECK` matches.
- `check_sharelatex_env_vars` enforces the SHARELATEX_* → OVERLEAF_* rename based on the configured image major version.

### `bin/docker-compose` — the compose assembler

The most complex script. On every invocation it:

1. Calls `read_image_version`, `read_mongo_version`, `read_config`, `check_retracted_version`, `check_sharelatex_env_vars`.
2. Calls `build_environment` → `canonicalize_data_paths` → `set_base_vars`, then conditionally `set_redis_vars`, `set_mongo_vars`, `set_sibling_containers_vars`, `set_logging_vars`, `set_nginx_vars`, `set_git_bridge_vars` based on the rc flags (`REDIS_ENABLED`, `MONGO_ENABLED`, `SIBLING_CONTAINERS_ENABLED`, `OVERLEAF_LOG_PATH`, `NGINX_ENABLED`, `GIT_BRIDGE_ENABLED`).
3. Each `set_*_vars` appends a `-f lib/docker-compose.<feature>.yml` flag to `DOCKER_COMPOSE_FLAGS`. If `config/docker-compose.override.yml` exists, it is appended last.
4. Exec `docker compose -p "$PROJECT_NAME" ${DOCKER_COMPOSE_FLAGS[@]} "$@"`. Falls back to `docker-compose` v1 with a deprecation warning if v2 is not present.

So the final compose file passed to docker is: `lib/docker-compose.base.yml` + version-appropriate vars file + zero-or-more feature fragments + optional user override.

### `lib/docker-compose.*.yml` — feature fragments

| File | Purpose | Enabled by |
| --- | --- | --- |
| `docker-compose.base.yml` | The `sharelatex` service itself | always |
| `docker-compose.vars.yml` | OVERLEAF_* env vars (image ≥5) | always (for ≥5) |
| `docker-compose.vars-legacy.yml` | SHARELATEX_* env vars | always (for <5) |
| `docker-compose.mongo.yml` | `mongo` service + replica set + healthcheck | `MONGO_ENABLED=true` |
| `docker-compose.redis.yml` | `redis` service (with optional `--appendonly yes`) | `REDIS_ENABLED=true` |
| `docker-compose.sibling-containers.yml` | mounts Docker socket for sandboxed compiles | `SIBLING_CONTAINERS_ENABLED=true` (Server Pro only) |
| `docker-compose.logging.yml` | bind-mounts host log dir to `/var/log/overleaf` | `OVERLEAF_LOG_PATH` is set |
| `docker-compose.nginx.yml` | NGINX TLS proxy in front of sharelatex | `NGINX_ENABLED=true` |
| `docker-compose.git-bridge.yml` | `git-bridge` service for git sync | `GIT_BRIDGE_ENABLED=true` (Server Pro ≥4 only) |

### `lib/default.rc` — defaults applied before `config/overleaf.rc`

Anything not set in `config/overleaf.rc` comes from here. **When adding a new option, add it here AND in `lib/config-seed/overleaf.rc`** so that fresh `bin/init` runs get the documented default.

### `lib/config-seed/`

The template directory copied into a fresh `config/` by `bin/init`. Contains:

- `overleaf.rc` — fully commented copy of all supported rc variables.
- `variables.env` — env var template (note `OVERLEAF_INVITE_TOKEN_SECRET` is generated by `bin/init`, not seeded).
- `version` — the default `IMAGE_VERSION` (e.g. `6.2.2`).
- `nginx.conf` — sample NGINX config with upstream + docker resolver.

### Config file roles (`config/`)

- `overleaf.rc` — top-level toolkit flags (image name overrides, feature toggles, host paths, ports).
- `variables.env` — environment variables loaded into the overleaf container (mail, LDAP/SAML, S3 filestore backend, etc.). The `SHARELATEX_*` → `OVERLEAF_*` rename happened in image 5.0.0.
- `version` — the docker image tag to pull. Sole input to `read_image_version`.
- `nginx/nginx.conf` + `nginx/certs/*.pem` — only when `NGINX_ENABLED=true`. Created by `bin/init --tls`.
- `docker-compose.override.yml` — optional user-supplied compose override, appended last.

### Brand rename across versions

The toolkit carries rename machinery because the project migrated from ShareLaTeX to Overleaf branding around image 5.0.0:

- `SHARELATEX_*` rc/env vars → `OVERLEAF_*` (handled by `bin/rename-rc-vars`, `bin/rename-env-vars-5-0`, and auto-called by `bin/upgrade` on a major-version boundary).
- Container paths `/var/lib/sharelatex` → `/var/lib/overleaf` and `/var/log/sharelatex` → `/var/log/overleaf` (gated by `IMAGE_VERSION_MAJOR < 5` in `bin/docker-compose` and `bin/logs`).
- The main service is still named `sharelatex` in the compose files — legacy name preserved.

If you touch anything brand-aware, update both the legacy (`< 5`) and modern (`>= 5`) code paths.


## Important cross-file invariants

- `config/version` is the single source of truth for which image runs; everything else (Mongo 6+ vs <6, OVERLEAF vs SHARELATEX var names, in-container paths, `HAS_WEB_API` for git-bridge) is derived from `IMAGE_VERSION_MAJOR/MINOR`.
- `lib/default.rc` and `lib/config-seed/overleaf.rc` must stay in sync — `read_config` sources them in that order, so any new variable needs to appear in both.
- `bin/docker-compose` is the only script that assembles `DOCKER_COMPOSE_FLAGS`. All other `bin/*` scripts that touch compose go through it (`bin/up`, `bin/start`, `bin/stop`, `bin/logs`, `bin/shell`, `bin/mongo`, `bin/run-script`).
- `bin/upgrade` is the only script that mutates `config/version` and `config/variables.env` on the user's behalf (with prompt), and is also the only one that calls `git -C "$TOOLKIT_ROOT" pull`.


## Common pitfalls when editing

- Always include `set -euo pipefail` and the toolkit-root-detection preamble; otherwise the script will silently run from the wrong cwd.
- When adding a new rc variable, also update `lib/config-seed/overleaf.rc` (it's the source `bin/init` copies from) and consider whether `lib/default.rc` needs a sensible default.
- When adding a new docker-compose fragment, follow the pattern in `lib/docker-compose.git-bridge.yml`: only declare the `sharelatex` service's additional config; never redefine `sharelatex` wholesale.
- Bash arrays (`DOCKER_COMPOSE_FLAGS`) must be expanded with `[@]` and double quotes. The compose wrapper depends on flag ordering for `depends_on`, `links`, etc.
- `SKIP_WARNINGS=true` is set when one script chains into `bin/docker-compose` (`bin/up`, `bin/mongo`) so the deprecation banners don't print twice. Honour that env var in any new warning you add to `bin/docker-compose`.


## CI / contribution

- PR template (`/.github/PULL_REQUEST_TEMPLATE.md`) requires the CLA confirmation box.
- Issue template (`/.github/ISSUE_TEMPLATE.md`) is for CE bugs only — Server Pro users go to `support@overleaf.com`.
- The toolkit itself has no automated test suite; `bin/dev/lint` is the only automated check.
- Editor config (`.editorconfig`): 2-space indent, LF, UTF-8, final newline, trim trailing whitespace. Shell scripts under `bin/` and `lib/` follow this style.
